# 항목별 간격 반복 학습 (오늘 학습) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 한자·단어를 항목별 복습 날짜로 관리하고, "오늘 학습" 한 화면에서 복습 N개 + 새 항목 M개를 풀게 합니다.

**Architecture:** 스케줄러·하루 새 항목 수·회차 구성·진도 옮기기를 DOM 없는 순수 모듈 `srs-core.js`(브라우저 `window.SrsCore`, Node `module.exports`)에 둡니다. `app.js`는 이 모듈을 불러 기존 `hz_srs` 큐를 한자 키(`h:<id>`)까지 넓히고, 오늘 학습 화면을 추가합니다. 화면 동작은 Playwright WebKit 스모크 테스트로 확인합니다.

**Tech Stack:** 정적 HTML/CSS/vanilla JS(빌드 없음), Node 내장 테스트 러너, Playwright 1.65.1(WebKit, devDependency).

**Spec:** `docs/superpowers/specs/2026-11-20-item-srs-design.md`

## Global Constraints

- 빌드 도구 없음. iPadOS Safari 15 이상 홈 화면 앱에서 동작. 새 스크립트는 `index.html`에서 `app.js`보다 먼저 로드하고 `sw.js` PRECACHE에 넣습니다.
- 진도 파일 형식 `version: 5` 유지. `hz_srs` 형식 `{b, due, n}` 유지.
- 상자 간격: 1 = 10분, 2 = 1일, 3 = 3일, 4 = 7일, 5 = 14일, 6 = 30일. 맞히면 +1(최대 6), 틀리거나 "모르겠어요"면 1.
- 처음 보기: 맞히면 상자 4, 틀리거나 "모르겠어요"면 학습 카드 후 상자 1.
- 회차 최대 20문제. 복습 먼저, 남는 자리에 새 항목.
- M = 올림(남은 새 항목 ÷ 남은 학습일), 상한 기본 40(설정 10~100). due가 지금 이전인 항목이 150개를 넘으면 새 항목 0.
- 진도 옮기기: 체크 항목 → 상자 2, 아는 항목 → 상자 4, 하루 30개씩 내일부터, 체크 먼저. `hz_srs_migrated: 1`로 한 번만.
- 키: 한자 `h:<카드 id>`(예: `h:0001`), 단어는 단어 문자열 그대로.
- 테스트: `node --test tests/`(단위), `node tests/e2e/today.e2e.cjs`(WebKit 스모크).

## Review Focus

1. 자정을 넘긴 회차: 오늘 본 새 항목 수가 현지 날짜 기준으로 0부터 다시 세져야 합니다. → Task 1 `newAllowedToday` 날짜 바뀜 테스트.
2. 복습 150개 경계: 150개는 새 항목 허용, 151개는 차단. → Task 1 테스트.
3. 시험일이 지났거나 남은 학습일 0: M 계산이 0으로 나누지 않고 상한 안의 값을 줍니다. → Task 1 테스트.
4. `hz_srs`에 데이터에 없는 키(예전 단어, 잘못된 `h:` id)가 있어도 복습 화면이 멈추지 않고 그 키를 건너뜁니다. → Task 3 스모크.
5. 옮기기를 마친 뒤 이전 진도 파일을 불러와도 옮기기를 다시 하지 않고, 기존 큐 항목을 덮어쓰지 않습니다. → Task 2 테스트(기존 키 건너뛰기) + Task 3 스모크(불러오기 후 `hz_srs_migrated` 유지).
