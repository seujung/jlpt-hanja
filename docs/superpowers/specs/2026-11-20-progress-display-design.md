# 학습 진행 표시 설계

## 의도

사용자가 "오늘 학습"을 해도 아래 일차 타일(`01일차`~`30일차`)에는 아무 변화가 없습니다.
일차 타일은 토리파 7단계 진도(`tpStepsDone`)만 세기 때문입니다(`app.js:604`).

개요 위쪽에는 전체 학습 범위 진행만 있고, 일정이 얼마나 지났는지는 보이지 않습니다.

사용자는 두 가지를 보고 싶어 합니다.

1. 전체 학습일 중 지금 며칠째인지
2. 일차별로 오늘 학습을 어디까지 마쳤는지

## 목표

- 일차 타일에 오늘 학습 기준 완료 항목 수를 표시합니다.
- 개요 계획 카드에 학습 일정 진행(`N / 전체일`)을 표시합니다.

## 목표가 아닌 것

- 토리파 7단계 진도 표시를 없애지 않습니다. 함께 둡니다.
- 학습 기록을 날짜별로 저장하지 않습니다.
- 진도 파일 형식을 바꾸지 않습니다.

## 결정 사항

### 완료의 정의

사용자가 고른 기준은 "복습까지 끝난 항목"입니다.
복습 상자(SRS 상자) 4 이상을 완료로 셉니다.
상자 4는 7일 뒤 확인까지 통과한 상태입니다(`srs-core.js:25`).

처음 볼 때 맞히면 바로 상자 4가 됩니다(`srs-core.js:25`).
4지선다라 찍어서 맞힐 확률이 25%입니다.
따라서 "완료" 수는 실제 암기 상태보다 앞설 수 있습니다.
이 한계는 받아들입니다.

### 전체 일자의 기준

전체 일자는 `studyDaysLeft()`가 돌려주는 값입니다(`app.js:1368`).
하루 새 항목 수를 계산할 때 쓰는 바로 그 값입니다.
N2 목표, 2027. 7. 4. 시험 기준으로 169일입니다.

### 진행 일수 계산

달력 경과일을 셉니다.
사용자가 고른 방식입니다.

- `hz_start`에 시작일(YYYY-MM-DD)을 저장합니다.
- 경과일 = `오늘 - 시작일 + 1`입니다.
- 값은 1 이상, 전체 일자 이하로 자릅니다.

시작일이 없으면 앱을 처음 열 때 오늘로 저장합니다.

## 접근 방식

| 방식 | 내용 | 대가 | 결정 |
|---|---|---|---|
| A. 저장 없이 항목 수로 환산 | `본 항목 ÷ 전체 × 전체일` | 날짜가 아니라 양이라 "며칠째"가 아닙니다. | 고르지 않음 |
| **B. 시작일 저장 + 달력 경과일** | `hz_start`를 저장하고 경과일을 셉니다. | `localStorage` 키가 하나 늘어납니다. | **고름** |
| C. 학습한 날만 세기 | 마친 날 수를 별도 저장합니다. | 밀린 날이 드러나지 않습니다. | 고르지 않음 |

B를 고른 이유는 시험일까지 남은 날을 그대로 보여 주기 때문입니다.
밀린 날도 경과일로 세므로 일정이 늦어지는 것을 알 수 있습니다.

## 설계

### 1. 시작일 저장

- 키 이름은 `hz_start`입니다.
- 값은 현지 날짜 `YYYY-MM-DD`입니다.
- 앱을 시작할 때 값이 없으면 `Srs.dayKey(Date.now())`로 저장합니다.
- 위치는 `migrateToripaOnce()` 옆입니다(`app.js:1692`).
- 진도 파일 내보내기와 불러오기에 `start`를 넣습니다(`app.js:25`, `app.js:53`).
  없으면 지금 값을 그대로 둡니다.

### 2. 일차별 완료 수

새 함수 `dayProgress(day)`를 둡니다.

```
dayProgress(day) → { done, total }
```

- 항목 목록은 `tpItems(day, "hanja", null)`과 `tpItems(day, "word", null)`입니다.
  레벨 필터를 걸지 않습니다. 일차 타일은 일차 전체를 보여 주기 때문입니다.
- 키는 `itemKey`와 같은 규칙입니다. 한자는 `h:<id>`, 단어는 단어 문자열입니다.
- `done`은 `srs[key] && srs[key].b >= 4`인 항목 수입니다.
- `total`은 항목 수입니다.
- 결과는 일차별로 캐시합니다. `saveSrs()`가 캐시를 비웁니다.
- 응답이 바뀌면 캐시를 다시 계산하므로 화면에는 즉시 반영됩니다.

### 3. 일차 타일 표시

`dayTile`(`app.js:712`)의 메타 줄을 바꿉니다.

```
지금:  한자 10자 · 토리파 3/7단계
바꿈:  한자 10자 · 완료 6/10
```

- 진행 막대는 완료 비율(`done / total`)로 채웁니다.
- 토리파 진행 막대는 없애지 않습니다.
  메타 줄 아래에 작은 줄로 따로 둡니다. 화면이 복잡해지면 빌더가 판단합니다.

### 4. 개요 계획 카드 표시

`planCard`(`app.js:1282`)의 타일에 한 칸을 더합니다.

```
학습 일정
37 / 169일
시작 2026. 11. 20.
```

- 전체 일자는 `studyDaysLeft()`입니다.
- 경과일은 2절의 시작일로 계산합니다.
- 전체 일자가 0 이하이면 `—`를 표시합니다.

### 5. 테스트

순수 함수로 분리한 계산만 테스트합니다.

- 경과일 계산: 시작일이 오늘, 어제, 미래, 전체 일자를 넘는 경우.
- `dayProgress`: 빈 큐, 상자 3과 4의 경계, 한자와 단어 합산.

## 실패로 보는 경우

- 일차 타일이 느려집니다. 화면을 열 때마다 30개 일차를 다시 계산하면 안 됩니다.
- 기존 진도와 토리파 표시가 사라집니다.
- 상자 3인 항목이 완료로 표시됩니다.

## 남는 위험

시작일은 처음 여는 날로 잡힙니다.
앱을 먼저 열어 두고 나중에 학습을 시작하면 경과일이 실제보다 앞섭니다.
이 경우 사용자가 설정에서 시작일을 고칠 수 있게 하는 편이 낫습니다.
이번 변경에는 넣지 않습니다.

## 빌더에게 맡기는 것

- 타일 배치와 문구.
- 캐시 구현 방식.
- 토리파 진행 막대와 완료 막대를 함께 둘지, 하나로 합칠지.
